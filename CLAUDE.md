# tyrbujac.com

Personal site + blog for Tyr Bujac. Design Engineer, final-year CS at Liverpool, relocating to Barcelona summer 2027.

## Stack

- **Astro** (static output, no client-side JS). Build step: `pnpm build` → `dist/`.
- Hosted on Netlify, deployed via GitHub push (`netlify.toml` sets `command` and `publish = "dist"`).
- One shared `public/styles.css` across all pages (referenced as `/styles.css`).
- TypeScript throughout (`tsconfig.json` extends `astro/tsconfigs/strict`).

## Structure

- `src/layouts/Base.astro` — shared `<head>`, `<header>`, `<footer>`. Props: `title`, `description`, `ogTitle?`, `ogType?`, `ogImage?`, `publishedTime?`. Named slot `head` for extra head content; named slot `header-inner` for page-specific header (default: `<a href="/">Tyr Bujac</a>`).
- `src/layouts/Post.astro` — wraps Base; renders `<article class="post">` with title, date, word count, and Article JSON-LD.
- `src/pages/index.astro` — homepage (about, projects, blog list queried from collection).
- `src/pages/projects/index.astro` — projects listing.
- `src/pages/blog/index.astro` — blog listing (queries collection, sorted newest first).
- `src/pages/blog/[slug].astro` — individual post route via `getStaticPaths`.
- `src/pages/rss.xml.js` — RSS feed.
- `src/content/config.ts` — blog collection schema (title, description, date, ogImage?).
- `src/content/blog/[slug].md` — blog posts as Markdown with frontmatter.
- `plugins/remark-word-count.mjs` — remark plugin that counts paragraph words before `## References` and injects into `remarkPluginFrontmatter.wordCount`.
- `public/` — static assets: `styles.css`, `assets/`, `robots.txt`.
- `tests/seo.test.ts` — Vitest SEO suite (runs against built `dist/`).

## Conventions

- Semantic HTML: `<header>`, `<main>`, `<section>`, `<article>`, `<footer>`.
- CSS custom properties for all colour, spacing, type tokens. Defined in `:root`. Don't hardcode values in component styles.
- Mobile-first responsive. `prefers-color-scheme` for dark mode (no toggle).
- Centred column, max-width ~42rem (~65ch).
- Type stack: system fonts. Body ~17px, line-height 1.6.
- No client-side JavaScript. No `'use client'`. No Astro islands.
- `trailingSlash: 'always'` — all internal links end in `/`.

## Blog posts

New posts: create `src/content/blog/[slug].md` with frontmatter:

```md
---
title: "Post title"
description: "One-sentence description for meta and og:description."
date: YYYY-MM-DD
---

Body prose...
```

- Body is plain Markdown. References section: `## References` followed by a `- [text](url)` list.
- **Word count is computed automatically** by `plugins/remark-word-count.mjs` at build time. It counts words in paragraph nodes before `## References`. Do not add a word count to frontmatter — it is injected at build time and rendered in `Post.astro`.
- Raw HTML works in `.md` files (used for `<figure>` blocks). Keep it minimal.
- After adding or editing a post, run `pnpm build` to verify the count and check for errors.

## SEO

- Run `pnpm test` to validate SEO after changes. Tests assert: title, description, canonical, OG tags, Article JSON-LD (posts), sitemap completeness, RSS feed, robots.txt, no `.html` internal links.
- Sitemap auto-generated by `@astrojs/sitemap` on each build.
- RSS feed at `/rss.xml`.
- Canonical URLs are absolute (`https://tyrbujac.com/...`), generated from `Astro.url.pathname` in `Base.astro`.

## Modern CSS — reach for these first

- `clamp()` for fluid type
- `:has()` for parent selectors
- Container queries where applicable
- `oklch()` over hex for new colours
- Logical properties (`margin-block`, `padding-inline`)

## Positioning

Site positions Tyr as a **Design Engineer** (Figma → React). Not "Product Designer" or "Frontend Developer." Don't soften this.

## Don'ts

- No npm packages beyond what's in `package.json` without asking. No React, no Tailwind, no UI libs.
- No client-side JS. If something seems to need it, push back first.
- No analytics, no cookies, no tracking.
- No "Hello world / welcome to my blog" posts. Posts should have substance.
- Don't add features without asking (tags, search, comments, pagination, etc. — these come later, deliberately).
